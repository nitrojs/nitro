# Nitro v3 RC is here!

> Bundleless mode, zero-config Vitest, a 5× smaller install, and more. Nitro v3 is now a release candidate, and the public API is stable.

Since the [last beta](https://github.com/nitrojs/nitro/releases/tag/v3.0.260903-beta), over 200 commits from more than 30 contributors went into this release, alongside many improvements across the [H3](https://github.com/h3js) and [UnJS](https://github.com/unjs) ecosystems that power Nitro. We added the last big features, tightened every corner of the API, and cleared out legacy code so that v3 stable can start clean. Here are the highlights.

## 📦 Bundleless Mode

Nitro has always been a build tool for servers. Now you can **skip the build entirely** and use it as a runtime.

```ts [nitro.config.ts]
import { defineConfig } from "nitro";

export default defineConfig({
  builder: false,
});
```

With `builder: false`, Nitro runs your server sources directly instead of bundling them. In production (with `nitro serve`), they load in the main process, or in a Node.js worker when you use `buildPlugins`. In development, they run in a worker that is replaced on every change. TypeScript, JSX, aliases, `import.meta.*`, `raw`/`text`/`bytes` imports and WebAssembly all work the same as in a bundled build. Files are transformed on demand, and virtual modules are served from memory.

If `rolldown` isn't installed, `nitro dev` now falls back to bundleless mode on its own. To start a new bundleless project, pick the **Runtime** template of `nitro create` (see Get Started below).

::note
Bundleless mode is still **experimental**.
::

:read-more{to="/config#builder"}

### 🚀 `nitro serve`

The new `nitro serve` command starts a production server straight from your sources, always in bundleless mode:

```sh
npx nitro serve
```

- **No build step.** Your sources run as they are, with nothing to compile ahead of time.
- **Production ready.** It handles WebSockets, scheduled tasks, public assets, `.env` files and graceful shutdown on `SIGINT`/`SIGTERM`.
- **Fast.** It uses the same compiled router in memory, and in our benchmark it served about as many requests per second as plain h3 on srvx.
- **Dev-friendly.** Run `nitro serve --dev` to watch your sources and restart on every change.

`nitro start` is an alias of `nitro serve`. `nitro preview` still serves only a build output.

:read-more{to="/docs/cli#nitro-serve"}

## 🧩 Build Plugins

The new `buildPlugins` option takes a single list of plugins that works with every builder: `rollup`, `rolldown`, `vite`, and even in bundleless mode.

```ts [nitro.config.ts]
import { defineConfig } from "nitro";

export default defineConfig({
  buildPlugins: [
    {
      name: "my-virtual-module",
      resolveId: {
        filter: { id: /^virtual:my-module$/ },
        handler: (id) => `\0${id}`,
      },
      load: {
        filter: { id: /^\0virtual:my-module$/ },
        handler: () => `export default "Hello!"`,
      },
    },
  ],
});
```

Plugins use the familiar Rollup plugin interface. The `resolveId`, `load` and `transform` hooks with a `filter` work with every builder. Nitro modules can add their own with `nitro.options.buildPlugins.push(plugin)`.

:read-more{to="/config#buildplugins"}

## 🧪 Vitest, Zero Config

Add `nitro()` to your Vite config and run `vitest`. That's it.

```ts [api.test.ts]
import { expect, test } from "vitest";
import { serverFetch } from "nitro";

test("GET /api/hello", async () => {
  const res = await serverFetch("/api/hello");
  expect(await res.json()).toEqual({ hello: "world" });
});
```

Tests run inside a `nitro` environment, where routes, plugins, runtime config and KV work exactly as in your server. You don't need to start a dev server. Each test file gets its own app, `vi.mock` works, and watch mode reruns tests when you change a route.

:read-more{to="/docs/testing"}

See the [Vitest example](/examples/vitest) for a complete project.

## 🔌 Server Entry Options

A `server.ts` can now configure the server it runs on. Wrap the default export with `defineServerEntry()` to get typed options:

```ts [server.ts]
import { defineServerEntry } from "nitro";

export default defineServerEntry({
  port: 8080,
  maxRequestBodySize: 1024 * 1024,
  fetch(req) {
    return new Response("Hello from server entry!");
  },
});
```

On the Node.js, Bun and Deno presets, these options go straight to [srvx](https://srvx.h3.dev/): `port`, `hostname`, `reusePort`, `protocol`, `tls`, `silent`, `gracefulShutdown`, `maxRequestBodySize`, `trustProxy`, and the runtime-specific `node`, `bun` and `deno` settings. Environment variables such as `NITRO_PORT` and `NITRO_HOST` still take precedence, so you can keep configuring the server at runtime.

:read-more{to="/docs/server-entry#server-options"}

## 🥟 Runtime-native dev server

`nitro dev` now runs natively on Bun and Deno. The dev server listens with the runtime's own server (`Bun.serve()` or `Deno.serve()` through [srvx](https://srvx.h3.dev/)) instead of going through the `node:http` compatibility layer.

```sh
bun --bun nitro dev
```

WebSockets use the adapter of the runtime your code runs in, and [`devProxy`](/config#devproxy) works too: HTTP requests are proxied with `fetch` and WebSockets with the crossws proxy. On Node.js, nothing changes.

## ☁️ Local Cloudflare

Durable Objects, Workflows and RPC service bindings now work in `nitro dev` and `vite dev`, with hot reload. Export them from `server.ts` and declare them in your Wrangler config:

```ts [server.ts]
import { DurableObject } from "cloudflare:workers";

export class Counter extends DurableObject {
  async fetch() {
    const count = ((await this.ctx.storage.get<number>("count")) || 0) + 1;
    await this.ctx.storage.put("count", count);
    return Response.json({ count });
  }
}

export default { fetch() {} };
```

Bindings and `waitUntil` also work in dev. The `cloudflare_durable` preset is merged into `cloudflare_module`: add a `$DurableObject` binding, and WebSocket upgrades go to a shared Durable Object with pub/sub and hibernation.

:read-more{to="/deploy/providers/cloudflare#durable-objects"}

## ▲ Vercel

ISR on Vercel is now explicit: only the [`isr`](/deploy/providers/vercel#on-demand-incremental-static-regeneration-isr) route rule turns it on. `swr` and `cache` rules use Nitro's built-in cache instead, the same as on every other platform. When you set `allowQuery`, those query params now also reach your handler.

Nitro also builds the Vercel routing config with rou3 now, the same router your app uses at runtime. The routes Vercel serves match the routes your app handles, including method-scoped rules, header-only rules and `redirect: false` exceptions.

The function runtime follows your `package.json`, picked from `engines.node` or `engines.bun` the same way Vercel does it. `event.waitUntil()` works with the Node.js runtime, and observability routes are always generated, whatever compatibility date you set.

:read-more{to="/deploy/providers/vercel"}

## ✨ More Highlights

- **H3 v2 stable and rou3 v1.** Nitro now runs on the stable releases.
- **KV storage.** `useStorage` is now [`useKV`](/docs/storage) from `nitro/kv`, and the `storage` option is now `kv`. The old names still work as deprecated aliases.
- **Dedicated cache storage.** Cached handlers and functions use built-in [`cache`](/docs/cache#cache-storage) drivers (`memory`, `fs` or `kv`). `cache.defaults` sets global defaults.
- **Async plugins.** `definePlugin(async (nitroApp) => { ... })` is supported. Requests wait until startup finishes, with no top-level await, so it works on every runtime.
- **Better HTTP semantics.**
  - `QUERY` method routes (`routes/search.query.ts`).
  - `405` with an `Allow` header when only other methods match.
  - `HEAD` requests served by `GET` routes.
- **Middleware runs before the cache.** Middleware now runs on cached routes, and the headers it sets stay out of cache entries.
- **Polyfill options.** `alias` and the new `inject`, `polyfills` and `builtinModules` options replace the `unenv` option. `unenv` is only installed when a build actually needs one of its polyfills.
- **tsconfig `paths` everywhere.** Path aliases from `tsconfig.json` now resolve with every builder (`rollup`, `rolldown`, `vite` and `false`), in dev and in production. Turn this off with `typescript.tsconfigPaths: false`.
- **Route rules match at the edge.** Netlify, Cloudflare Pages and EdgeOne configs now use rou3 patterns too, so platform routing matches the runtime. Method-scoped keys like `"GET /old/**"` work at runtime and in Vercel and EdgeOne configs.
- **Dev experience.**
  - Chrome DevTools [workspace folders](/config#devserver).
  - Unix sockets with `NITRO_UNIX_SOCKET`.
  - Support for Vite 8's experimental bundled dev mode (`experimental.bundledDev`).
  - Many stability fixes for the Vite and Nitro dev servers.
- **Builder API.** `startPreview()` and `deploy()` are exported from `nitro/builder` for tools.

## 🏁 Get Started

Nitro now has a built-in `nitro create` command, which replaces `create-nitro-app`:

::code-group
```sh [npm]
npx --min-release-age=0 nitro@latest create
```
```sh [pnpm]
pnpm dlx --config.minimum-release-age=0 nitro@latest create
```
::

::note
The `--min-release-age=0` (npm) and `--config.minimum-release-age=0` (pnpm) flags skip any minimum release age you have configured, so you get the RC on release day.
::

Pick a template:

- **Vite:** a full-stack app with a frontend.
- **Rolldown:** an API server, bundled for production.
- **Runtime:** an API server with no build step, using bundleless mode (experimental).

## 🔄 Migrating from Beta

Most beta apps upgrade without changes. Check this list first:

- **Node.js `>=22.22.0`** is now required.
- **Pin your builder:** add `rolldown`, `rollup` or `vite` to your `devDependencies`.
- **Cache entries are now in memory by default,** unless you mount a `cache` storage. To use KV storage anyway, set `cache: { driver: "kv" }`.
- **Reserved file suffixes:** a file like `routes/hello.world.ts` now fails the build. Rename it, or allow the suffix with `scanSuffixes`.
- **Named catch-alls** like `routes/docs/[...slug].ts` now also match `/docs`.
- **Renamed hooks:** `rollup:before` → `build:config`, `rollup:reload` → `build:reload`.
- **Vite options:** `experimental.vite.*` → `vite.*`.
- **Polyfill options:** the `unenv` option is deprecated. Use `alias`, `inject`, `polyfills` and `builtinModules` instead.
- **Hooks merge:** a hook in your config no longer replaces the preset's hook with the same name. Both run, the preset's first.
- **tsconfig `paths`:** with `rollup` and `rolldown`, `paths` that map package names to source files are now used, so those sources get bundled.
- **Removed options:** `netlify.images`, `vercel.regions`, `prerender.retry` and `prerender.retryDelay`, deprecated in earlier prereleases, are removed.
- **Presets:**
  - `cloudflare_durable` → `cloudflare_module`
  - `exports.cloudflare.ts` and the `cloudflare.exports` option are removed. Export your Durable Objects, Workflows and entrypoints from `server.ts` instead.
  - The deprecated `event` field is removed from the `cloudflare:email` and `cloudflare:queue` hooks.
  - Cloudflare Pages and EdgeOne no longer prefix `baseURL` onto relative `redirect` targets.
  - `deno_deploy` → `deno_server`
  - `platform_sh` → `upsun`
  - `winterjs` is removed.
  - Netlify output moved to `.netlify/v1`.
  - Azure uses the Functions v4 model by default.
  - Vercel `future.nativeSWR` is removed; use the `isr` route rule.

For more details, see the [migration guide](/docs/migration).
